# 📚 Page2Page — Платформа студенческого буккроссинга и обмена литературой

## 1. Общее описание проекта
**Page2Page** — это современная веб-платформа для студенческого буккроссинга, созданная для обмена прочитанными книгами, учебниками, методичками и мангой внутри университетского сообщества. Проект решает проблему поиска нужной учебной или художественной литературы без лишних затрат, продвигая культуру осознанного потребления и шеринга.

Архитектура проекта построена по принципу клиент-серверного приложения:
* **Фронтенд:** Интерактивный пользовательский интерфейс с динамической фильтрацией, поиском и адаптивным дизайном.
* **Бэкенд:** RESTful API на базе **Node.js (Express)**, обеспечивающий безопасную обработку данных, аутентификацию, ролевой доступ и взаимодействие с базой данных.

## 🚀 Детальный функционал и возможности системы

1. **Модуль аутентификации и авторизации (Auth):**
   * Регистрация новых пользователей с валидацией полей (университетский email, хэширование паролей через `bcrypt`).
   * Авторизация с использованием JWT (JSON Web Tokens) для безопасного доступа к защищенным маршрутам.
   * Управление сессиями и защищенные защитой от CSRF/XSS эндпоинты.

2. **CRUD-операции с объявлениями (Книги / Манга):**
   * Создание объявления: указание названия, автора, жанра, состояния книги (новая, б/у, идеальное), описания и статуса.
   * Редактирование и удаление собственных объявлений пользователями.
   * Автоматическое изменение статусов: *«Доступна»* ➔ *«Забронирована»* ➔ *«Отдана/Обменяна»*.

3. **Медиа-менеджер (Загрузка обложек):**
   * Загрузка изображений обложек через multipart/form-data.
   * Валидация расширений и размера файлов на стороне сервера Node.js с сохранением в файловую систему или облачное хранилище.

4. **Продвинутый серверный поиск и фильтрация:**
   * Поиск по подстроке (название книги, имя автора, ключевые слова).
   * Фильтрация на стороне сервера с использованием query-параметров (`?genre=manga&status=available&sort=popular`).
   * Пагинация выдачи для оптимизации запросов к базе данных.

5. **Система бронирования и интерактивных отзывов:**
   * Оформление запроса на бронирование конкретного издания.
   * Публикация рецензий и отзывов о прошедших обменах с системой оценки (рейтинг от 1 до 5 звезд).

## 👥 Расширенная ролевая модель пользователей

В системе предусмотрено 5 детализированных ролей, каждая из которых имеет строго разграниченные права доступа (RBAC — Role-Based Access Control):

### 1. Гость (Guest / Unauthenticated)
* **Назначение:** Посетитель сайта, не прошедший регистрацию.
* **Права:**
  * Просмотр главной страницы, каталога книг и публичных объявлений.
  * Использование базового поиска и фильтрации по каталогу.
  * Просмотр подробной информации об отдельных книгах (без возможности бронирования и связи с владельцем).
  * Доступ к страницам регистрации и входа.
* **Уровень системы:** Публичный уровень (доступ к открытым GET-запросам без токена).

### 2. Обычный пользователь (User / Student)
* **Назначение:** Полноправный участник платформы — студент или преподаватель, осуществляющий обмен литературой.
* **Права:**
  * Регистрация, вход в систему и редактирование данных личного профиля (аватар, био, контакты).
  * Создание, редактирование и удаление собственных объявлений о книгах/манге (включая загрузку фото).
  * Отправка запросов на бронирование чужих книг и управление своими активными бронями.
  * Публикация отзывов и оценок после завершения обмена.
  * Использование расширенного поиска и добавление книг в «Избранное».
* **Уровень системы:** Клиентский защищенный уровень (доступ к эндпоинтам через валидный JWT-токен пользователя).

### 3. Модератор контента (Moderator)
* **Назначение:** Обеспечение порядка в каталоге, проверка честности объявлений и разрешение споров между участниками.
* **Права:**
  * Просмотр, редактирование или принудительное удаление объявлений, нарушающих правила платформы (спам, нецензурная лексика, запрещенная литература).
  * Модерация отзывов и рецензий (удаление оскорбительных комментариев).
  * Разрешение спорных ситуаций, связанных со срывом договоренностей об обмене.
  * Доступ к специальной панели модератора для быстрого просмотра жалоб.
* **Уровень системы:** Промежуточный серверный уровень (middleware проверки прав `isModerator` на уровне REST API).

### 4. Контент-менеджер / Администратор каталога (Catalog Manager)
* **Назначение:** Поддержание актуальности структуры разделов, жанров и тегов на платформе.
* **Права:**
  * Управление глобальными справочниками системы: добавление, переименование и удаление категорий, жанров, тегов и издательств.
  * Курирование подборок «Книга недели» или «Популярная манга» на главной странице.
  * Помощь модераторам в систематизации книжного фонда.
* **Уровень системы:** Административный уровень управления контентными метаданными.

### 5. Администратор системы (Super Admin)
* **Назначение:** Высший уровень доступа, полный технический и административный контроль над инфраструктурой приложения.
* **Права:**
  * Управление всеми учетными записями пользователей (изменение ролей, блокировка нарушителей, удаление аккаунтов).
  * Полный доступ ко всем таблицам базы данных и системным логам сервера Node.js.
  * Настройка глобальных параметров конфигурации платформы.
  * Право назначать других пользователей модераторами или контент-менеджерами.
* **Уровень системы:** Суперпользователь (абсолютный доступ ко всем модулям бэкенда, защищенным маршрутам и управлению базой данных).
